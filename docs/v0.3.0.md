# PaperSeek v0.3.0 更新说明

`v0.3.0` 重构了从研究问题到候选文献的执行方式。检索不再依赖只按固定次数推进的线性流程，而是把意图、查询、数据源观察、候选来源、恢复决策和排序阶段保存在显式状态中。用户仍然获得结果、CSV 和历史，并可通过新的持久 `run_id` MCP 工具审查、恢复和取消运行。

## 升级前注意

- 最低 Python 版本调整为 **Python 3.12**。
- 从 PyPI 升级可运行 `python -m pip install --upgrade paperseek`。
- 从 Git 仓库安装时，拉取新版本后运行 `python -m pip install -e ./backend`。
- 使用 MCP 时独立安装同版本 `paperseek-mcp==0.3.0`。
- v0.2 `.env` 不会被运行时继续读取。先运行 `paperseek migrate --legacy-env .env.v0.2 --output-env .env`，检查仅包含变量名的迁移报告，再加载新文件。

## 结构化检索计划

PaperSeek 会先把研究问题整理为 `SearchPlan`，包括：

- 用户要解决的核心问题与问题类型；
- 核心概念、必须同时满足的条件和可选扩展条件；
- 概念之间必须成立的关系；
- 同义表达、相邻概念、边界条件和仍需区分的歧义；
- 面向所选数据源的互补查询视角。

查询生成与后续修订统一使用结构化 JSON 输出。每个数据源都有自己的查询契约和语法预检；模型返回缺字段、截断内容、解释文字混入查询或数据源不接受的语法时，系统会要求重新生成，而不是把不完整字符串直接发送给数据源。

## Query Portfolio 与候选账本

单一检索式容易受术语体系影响。`v0.3.0` 会规划至少三个互补查询视角，并在当前预算内选择有效且不重复的视角执行。视角可以覆盖直接术语、相邻命名体系、机制或方法等不同入口，但不会无界扩张请求。

候选账本记录每篇论文来自主查询、哪个补充视角、哪条多路召回路线或引用扩展，并记录去重、截断和恢复信息。这样可以区分“数据库没有返回”“查询视角没有新增候选”和“候选在后续排序中被降权”等不同情况。

## 可恢复检索循环

检索循环现在由显式状态和预算契约驱动，并统一使用内置原生执行器。该路径负责查询校验、检索决策、恢复策略和候选队列审计。

系统会在安全阶段保存检查点。用户停止检索、上游网络临时失败或排序批次部分失败时，已取得的查询、候选、事件和部分结果会保留；Web UI 与历史接口可以从最近检查点恢复。恢复不会写入 API Key。

## 检索预算

Web UI、CLI、API 和 MCP 使用同一组预算：

| 预算 | 查询软上限 | 查询视角 | 每路召回配置上限 | 融合池 | LLM 候选 | 引用扩展（seed / 每 seed / 总新增 / 深度） |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| `fast`（默认） | 5 | 3 | 500 | 3000 | 256 | 3 / 4 / 40 / 2 |
| `medium` | 7 | 3 | 750 | 4500 | 384 | 8 / 6 / 80 / 2 |
| `high` | 9 | 4 | 1000 | 7000 | 512 | 16 / 8 / 160 / 3 |
| `max` | 12 | 6 | 1000 | 10000 | 1024 | 30 / 10 / 320 / 3 |

`fast` 使用最少的请求与候选容量；检索预算不会覆盖模型服务自身的思考设置。预算是统一预设，不会把最终展示数量限制为 `TARGET_MAX`；数据源命中量较大但候选池已适合后续排序时，也不会为了逼近 `TARGET_MAX` 而反复收窄。

## 候选召回、引用与排序

- 按数据源能力执行相关性、语义、影响力、时效性或本地质量等召回路线。
- 使用 DOI、数据源 ID 和规范化标题去重，再以 BM25、词项覆盖、本地 hashing cosine 和 RRF 进行轻量预排序。
- 支持的数据源可并行请求独立路线；融合顺序保持确定，避免网络完成顺序改变结果。
- OpenAlex 引用扩展按相关性、影响力和时效性选择不同种子，并在扩展后重新执行本地融合。
- LLM 排序按批次执行，出现超时、限流、漏项或部分失败时只重试受影响批次，并逐级降低并发；最低并发仍失败时保留本地预排序结果。

## Web UI 变化

Search 页按四个阶段展示：

1. 检索意图与检索式；
2. 检索迭代；
3. 候选召回与排序；
4. 文献结果。

当前阶段自动展开，已完成阶段折叠为关键摘要，用户手动展开或折叠后不会被后续流式事件重置。Query Portfolio 与普通迭代分开显示；候选账本、恢复原因和原始日志默认折叠。错误发生时，对应阶段和系统日志会自动展开。检索完成后页面不会自动跳走，用户可以先审阅流程，再打开 Results 或 Citation Map。

## 断代边界

- v0.3.0 只保留 `paperseek serve / worker / search / doctor / migrate / version` 六个正式 CLI 命令；旧 Python Agent API、旧命令和旧配置读取分支不提供兼容入口。
- 历史 SQLite 与旧 `.env` 通过显式 `paperseek migrate` 一次性转换；迁移不会猜测语义变化的旧配置。
- WoS Starter 仍需有效 API Key，database 选择通过 `PAPERSEEK_WOS_DB` 或正式 CLI/API 配置提交。
- 外部 LLM、embedding、reranker 和数据源仍受各自的配额、限流和可用性影响。PaperSeek 会尽量保留部分结果并回退，但无法保证第三方服务的 SLA。
